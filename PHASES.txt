PHASE 3 — Trending nearby (crowd signal)                            [ ]
============================================================================
Goal: hint places frequented by the broader user base, even if no friend
has tagged them.

Tasks:
[ ] Cloud Function onPostCreate trigger — increments
    places/{placeId}.globalVisitCount and updates lastVisitedAt.
    Idempotent: derive (postId,placeId) and skip on retry.
[ ] Map "trending" query: places.where(geohash within bounds)
    .orderBy("globalVisitCount","desc").limit(20). Reuse the geohash
    bounds helper from findOrCreatePlace.
[ ] Same geohash-bound query path also feeds the PlacePicker so the user
    sees nearby places tagged by OTHER users — not just their own. Needs
    a small Swift port of geofire-common's geohashQueryBounds, or a new
    "nearbyPlaces" callable that wraps it server-side.
[ ] Visual distinction:
    - Friend pin → accent color, with avatar.
    - Trending pin → dim/secondary color, "👥 N" badge for count, no
      identity revealed.
[ ] Privacy: never expose WHO visited a trending pin — count only.
[ ] DECISION OPEN: minimum visit threshold to surface (proposed: ≥3) so
    one-off taggings don't clutter the map.

PHASE 5 — Discovery achievements                                    [ ]
============================================================================
Goal: badges reward exploration, not arbitrary milestones. All driven by
Cloud Function triggers (no client claims = no cheating).

Proposed triggers (review/cull before implementing):

  Pioneer       — First to create a places/ doc (created:true return
                  from findOrCreatePlace).
  Wanderer      — 5 distinct places tagged in a calendar month.
  Local Guide   — A place YOU pioneered hits 10 globalVisitCount.
  Tastemaker    — A place you pioneered visited by 3+ non-friends.
  Loyal         — 5 posts at the same place. Counter on
                  users/{uid}/placeStats/{placeId}.
